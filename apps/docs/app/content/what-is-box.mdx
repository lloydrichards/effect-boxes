# What is Box?

## The problem

Formatting text for the terminal sounds simple until you need columns,
alignment, or nested structures. Consider printing a two-column layout:

```txt
Name        Age
Alice       30
Bob         25
```

With raw strings you track widths manually, pad by hand, and hope nothing
breaks when content changes. Add ANSI colors and the math gets worse because
escape sequences are invisible characters that inflate string length without
adding visual width.

## The mental model

A Box is an immutable rectangle of text with known dimensions. Every box
knows its width (columns) and height (rows). You compose boxes by placing
them beside each other or stacking them:

```txt
hcat:    ██ ██ + ░░      =  ██ ██ ░░
                 ░░               ░░

vcat:    ██ ██ + ░░ ░░ ░░  =  ██ ██
                              ░░ ░░ ░░
```

When boxes have different sizes, alignment controls where the smaller
box sits within the larger dimension.

Every operation returns a new Box. Nothing mutates. The result is always
another rectangle you can compose further.

## Annotations separate content from presentation

Boxes hold text. Annotations attach metadata (styling, semantics, identifiers)
without affecting layout. A Box doesn't know about colors; it knows it has an
annotation of some type `A`.

Reuse the same composition operations for each output target:

- Plain text, with annotations ignored
- ANSI terminal output, with annotations interpreted as colors and effects
- HTML, with annotations interpreted as elements and attributes

The generic type `Box<A>` captures this: `A` is whatever your renderer
understands.

## Renderers: one layout, many outputs

A Renderer translates `Box<A>` into a string for a specific target. The
library ships with three:

| Renderer | Reads annotations as | Output                |
| -------- | -------------------- | --------------------- |
| Plain    | (ignored)            | Raw text              |
| Ansi     | `AnsiStyle`          | Terminal escape codes |
| Html     | `HtmlAnnotationData` | HTML markup           |

The layout operations work with any annotation type. ANSI and HTML renderers
interpret different annotation types, so change the annotations when changing
targets. The plain renderer ignores annotations from either target.

For your first layout, use `Box.renderPlainSync` to get a string directly.
Effect layers supply renderer services inside Effect programs. See
[Rendering](/guides/rendering) when you need that approach.

## Where it fits

effect-boxes sits between your data and its display:

```txt
       ┌───────────────┐   ┌─────────────────┐
Data → │ compose Boxes │ → │ choose Renderer │ → Output String
       └───────────────┘   └─────────────────┘
```

It handles:

- Text measurement (including Unicode, emojis, East Asian characters)
- Alignment and padding
- Nested composition at any depth
- Annotation propagation through the tree

It does not handle:

- Writing to the terminal. Use `console.log` or Effect's `Console` for ordinary
  text lines. Use `Terminal.display` for exact writes that include cursor-control
  commands, as shown in [Using Cmd](/guides/using-cmd).
- Reading keyboard input. The [Select prompt tutorial](/tutorials/select-prompt)
  uses Effect's `Prompt.Custom` from `effect/cli` to build an interactive menu.
- Animation or state management
